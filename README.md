# Obscura Backend v2

The backend for Obscura, an AI study assistant for Sri Lankan O/L and A/L students. It replaces the previous Python/Railway backend with a NestJS modular monolith that serves:

- The **Flutter mobile app** via `POST /chat/ask` (text chat, grounded in real past exam papers)
- The **ESP32 study-robot firmware** via `POST /voice/ask` (voice pipeline)

Every curriculum-content answer is retrieved from real past-paper content (hybrid pgvector + full-text search, reranked, then generated by Gemini) and must be grounded in a cited source — the assistant is required to decline rather than answer from general knowledge when it has no relevant excerpt. See `SPEC-SHEET.md` for the full product/system design and `IMPLEMENTATION-PLAN.md` for the phased build plan this repo is being built against.

## Architecture

A single NestJS process (Nest CLI **monorepo**: one `apps/api` entry point + several `libs/*`) exposes public HTTP/WebSocket endpoints through a **Gateway** and runs every backend capability as its own Nest module — each also bound as an **in-process gRPC microservice** on `127.0.0.1`. Internal service-to-service calls always go over gRPC, never HTTP.

```
                         ┌─────────────────────────────────────────┐
                         │              apps/api (Nest)             │
  Mobile app  ──HTTP──▶  │  Gateway (HTTP/WS, guards, composition)  │
  ESP32 robot ──HTTP──▶  │                                           │
                         │   ┌────────┐ ┌─────┐ ┌──────────┐        │
                         │   │  Auth  │ │ RAG │ │ Chat/LLM │  ...   │
                         │   └────────┘ └─────┘ └──────────┘        │
                         │        all bound as gRPC on 127.0.0.1     │
                         └─────────────────────────────────────────┘
                                   │              │
                          Supabase Postgres   Gemini / Cohere
                        (pgvector + tsvector)   (embed/generate/rerank)
```

**Services** (`libs/*`, each a Nest module + its own gRPC contract in `libs/proto/src/*.proto`):

| Service | Status | Responsibility |
|---|---|---|
| **Auth** (`auth-service`) | ✅ live | Verifies Supabase JWTs (JWKS/RS256), resolves the `{student\|admin}` principal used by the Gateway's `AuthGuard`. Phase 2 adds device-key verification for the robot. |
| **RAG** (`rag-service`) | ✅ live | Hybrid retrieval: pgvector cosine similarity + Postgres full-text search, fused via Reciprocal Rank Fusion, reranked with Cohere `rerank-v3.5`, filtered by a minimum relevance threshold. |
| **Chat/LLM** (`chat-service`) | ✅ live | Builds a grounded prompt from retrieved excerpts, calls Gemini for a structured JSON answer, resolves citations back to real chunk metadata, and retries once with a stricter prompt if a curriculum question comes back uncited — this is what enforces the "never hallucinate" rule. |
| **Gateway** (`gateway`) | ✅ live | Public HTTP surface, `AuthGuard`/`DeviceAuthGuard`, security hardening (helmet/CORS/rate-limiting/request-id logging), and `AskService` — the shared orchestration core (RAG search → Chat/LLM ask → persist) that both `POST /chat/ask` and `POST /voice/ask` call. |
| **Speech** (`speech-service`) | ✅ live (Phase 2) | Google Cloud Speech-to-Text / Text-to-Speech for the voice pipeline. English/Tamil only at launch — Sinhala is explicitly rejected on the voice path (with a synthesized spoken decline). |
| **Ingestion** (`ingestion-service`) | ✅ live (Phase 3) | BullMQ worker that turns uploaded past-paper PDFs into embedded, searchable `paper_chunks` (Gemini multimodal structural extraction, with a `pdf-parse` fallback), pushing live status over WebSocket. |

**Shared libraries:** `libs/common` (validated env config), `libs/database` (raw `pg.Pool` access — **no ORM**, all SQL is hand-written and versioned as Supabase CLI migrations under `supabase/migrations/`), `libs/proto` (`.proto` contracts + `ts-proto`-generated TypeScript).

**Data:** Supabase Postgres (pgvector + tsvector) is the only datastore; Supabase Storage will hold raw PDFs (Phase 3); Upstash Redis backs a BullMQ ingestion queue (Phase 3).

## Running locally

**Prerequisites:** Node.js 20 LTS, npm (no yarn/pnpm), a Supabase project (pgvector enabled), a Gemini API key, a Cohere API key.

```bash
npm install

cp .env.example .env
# fill in .env: SUPABASE_URL / SUPABASE_ANON_KEY / SUPABASE_SERVICE_ROLE_KEY / SUPABASE_JWKS_URL,
# DATABASE_URL, REDIS_URL, GEMINI_API_KEY, COHERE_API_KEY
# (AUTH_GRPC_URL / RAG_GRPC_URL / CHAT_GRPC_URL / SPEECH_GRPC_URL already default to 127.0.0.1:5005x)

npm run proto:gen   # generate TypeScript from libs/proto/src/*.proto
npm run build
npm run start:dev   # or: node dist/apps/api/src/main.js after `npm run build`
```

`docker-compose.yml` provides a local Postgres (pgvector) + Redis stack as an alternative to pointing straight at a hosted Supabase/Upstash project:

```bash
docker compose up -d postgres redis
```

**Tests:**

```bash
npm test          # unit tests (libs/**/*.spec.ts)
npm run test:e2e  # e2e tests (apps/api/test/*.e2e-spec.ts) — these boot real gRPC
                   # microservices and, for RAG/Chat, call the live Gemini/Cohere APIs
```

## Implementation status

Being built via `IMPLEMENTATION-PLAN.md`'s 65-task phased plan (Phase 1: text chat end-to-end → Phase 2: voice pipeline → Phase 3: PDF ingestion + admin tooling). Current progress:

- **Phase 1 (text chat) done:** provisioning, NestJS monorepo scaffold, validated env config, Docker Compose, proto tooling, Postgres schema, database layer, Auth Service + Gateway `AuthGuard`, HTTP hardening, RAG Service (hybrid retrieval + rerank + gRPC), Chat/LLM Service (grounded prompt builder, Gemini wrapper, citation resolver with grounding retry, gRPC), the Gateway's `AskService` orchestrator, chat session/message persistence, and the `POST /chat/ask` controller. Confirmed working end-to-end on a real mobile device (sign-up, login/logout, authenticated chat screen).
- **Phase 2 (voice pipeline) done:** Speech Service (Google Cloud STT/TTS, English/Tamil only), wired as an in-process gRPC microservice, the device-authed `POST /voice/ask` controller (multipart WAV upload, headerless-PCM response), and the synthesized spoken decline for Sinhala-over-voice requests.
- **Phase 3 (PDF ingestion) done:** BullMQ ingestion queue/worker, admin-only `POST /papers/upload`, Gemini multimodal PDF structural extraction with a `pdf-parse` fallback, chunk embedding + `paper_chunks` upsert, live `paper:ingestion_status` WebSocket push, `GET /papers`/`GET /papers/:id`, per-admin daily upload rate limit, and the citation-rate admin metric.
- **Left:** end-to-end manual verification of the deployed voice and ingestion paths, and deploying to Railway (see Deployment below) — the actual remaining gap before this backend is fully shipped.

Detailed task-by-task history — what was built, every code review, every fix — lives in the (gitignored) SDD execution ledger at `.superpowers/sdd/IMPLEMENTATION-PLAN/progress.md` for anyone continuing this work.

## Deployment

Target platform is **Railway** (one service running the single compiled NestJS process — see `Dockerfile`; switched from an originally-planned Koyeb deployment after persistent Koyeb dashboard issues). Railway CLI is installed; the container build required two Alpine-specific fixes (`libc6-compat` for `grpc-tools`' glibc-only `protoc` binary, and temporary build tools for `bcrypt`'s native compile) — see `Dockerfile` for details. Phase 1/2/3 each end with their own deploy task once each phase's features are complete and verified; deploy is in progress as of this writing.
